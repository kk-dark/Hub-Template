# 发布说明模板

本文用于创建单个版本的发布说明。发布时替换所有占位内容，删除不适用的章节。

```markdown
# vX.Y.Z

稳定版

<发布者> 发布于 <发布时间> | <提交数量> 次提交

在此版本后已推送到 `<目标分支>`。

## Features

- <新增功能及其用户价值>（#<议题编号>）
- <新增功能及其用户价值>（#<议题编号>）

## Changes

- <行为、接口或配置变更>（#<议题编号>）
- <内部实现或工程结构变更>（#<议题编号>）

## Fixes

- <修复的问题和受影响的场景>（#<议题编号>）
- <修复的问题和受影响的场景>（#<议题编号>）

## Other

- <文档、构建、依赖或其他维护事项>（#<议题编号>）

## Contributors

- @<用户名>
- @<用户名>

## New Contributors

- @<用户名> 首次参与贡献（#<议题编号>）。

## Full Changelog

[比较 vA.B.C...vX.Y.Z](<完整变更记录地址>)

## 下载附件

- `<项目名>_X.Y.Z_checksums.txt`
- `<项目名>_<平台>_<架构>.<格式>`
- 源代码（ZIP）
- 源代码（TAR.GZ）
```

## 填写规则

- 版本号遵循 [版本控制规范](../VERSIONING.md)。
- 只保留实际发生变化的章节。没有对应内容时删除该章节。
- 功能、变更和修复应说明用户可感知的结果，并关联真实 Issue 或 PR 编号。
- `Contributors` 列出参与本版本的贡献者，`New Contributors` 只列出首次贡献者。
- 完整变更记录链接应比较上一个版本和当前版本，例如 `v1.11.0...v1.12.0`。
- 附件名称必须与实际发布的校验文件、压缩包和源代码归档一致。
